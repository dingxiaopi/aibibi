# v0.3.0 · 分组采集与首次真实报价教程

发布日期：2026-11-02。代码采用 MIT，运营数据与品牌范围继续按仓库的独立说明处理。

## 新增与改进

- 增加[从零到第一条真实报价](../first-quote.md)的中文教程：独立本地实例、原店货架、人工详情审核或 AI 分类、映射建立、分批推送与服务器回执，之后再接线上部署和私有 Actions。
- 加密状态新增 `vps_sample`、`vps` profile；VPS profile 路由到私有自托管节点，普通 profile 保持原托管节点选择，不自动回退。
- hosted/vps 分组独立保存状态、共享串行队列。来源需由运营者明确分配，不自动发现或调度。
- 自托管节点成功保存远程密文后才删除明文。旧明文仍在时，下一轮在检出之前停止，保护尚未保存的进度。
- 密文 Git 上传最多重试 5 次，使用 HTTP/1.1；失败保留进度，不重复采集或修改观察时间。
- VPS 使用持久的本地 npm 缓存，避免任务收尾重复上传远程依赖缓存；托管节点继续使用 Actions 缓存。

## 从 v0.2.0 升级

1. 保留自己的忽略目录、配置、凭据和已完成批次，再检出 v0.3.0。普通本地更新命令保持兼容。
2. 使用 Actions 时，把本版本 `ops/github-actions/collect.yml` 同步到自己的私有状态仓库，将 `APP_REF` 固定为自己已审核的 v0.3.0 完整提交 SHA。
3. 需要 VPS 时，先在自己的私有仓库注册专用 runner，配置 `COLLECTOR_VPS_RUNNER_LABELS`，独立准备 `vps_sample` 和 `vps` 密文。从小范围 probe 和 update 开始，并核实服务器回执。
4. hosted 与 vps 的来源、映射和快照范围必须互不重叠；样本不是自动更新的副本。已有失败明文先恢复或核实远程加密保存，不直接删除。
5. 新安装先完成首次商品审核，再交给 `--no-ai` 的日常采集。代码升级不自动批准商品或更新自己的规格库。

本次没有 Worker/前端运行时代码或数据库迁移变化。仅使用更新后的采集工具/工作流不需要重新部署网站；自己的站点身份、域名或网站代码变化仍需重建部署。

## 验收范围

- 从公开仓库全新克隆，安装锁定依赖；131项Python、93项Node/Worker、类型检查、构建 dry-run 与独立 demo 初始化通过。
- 新实例从空映射开始，在隔离本地 Worker + D1 上完成原店采集、完整详情人工审核、重新读取核验批准、真实报价推送和服务器3/3批完整回执核对；公开查询有1个有价规格、1条有效有货报价，后台401/登录200符合预期。没有复制生产映射、使用生产令牌或写入运营站。
- 用独立密钥核对所有 profile 的状态加密/恢复与身份隔离。VPS 留存保护与清理顺序、上传重试已验证；真实分组采集已在运营者私有仓库另行验收。

采集仍为手动，没有安装定时器。开源仓库不包含原运营实例的真实店铺清单、报价、审核映射、私有密文或服务器权限。
