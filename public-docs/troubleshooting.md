# 常见问题与反馈

新安装建议先走[从零到第一条真实报价](first-quote.md)，包含不依赖 AI Key 的人工详情审核路径。

## 我只想试用，需要先准备数据库或 AI Key 吗？

不需要。README 中的 `npm run demo` 会初始化独立的本地数据库并导入虚构数据。
它不访问真实店铺，不运行 AI 审核，也不会创建 Cloudflare 线上资源。
演示店铺的 `.example` 链接不可用于购买。

## 启动失败，先提供哪些信息？

先确认 Node.js 为 22.18 或更高版本，以及是否在 `cloudflare/` 目录执行了 `npm ci`。
实际采集另需 Python 3.9+，目前支持 macOS / Linux；Windows 用户可在 Linux 环境中运行采集器。

反馈时附项目版本、操作系统、Node/Python 版本、复现步骤和脱敏后的错误摘要。
不用上传 `.dev.vars`、`.env.ai-review`、整个实例目录或完整日志。

## 8787 端口被占用

先确认占用者是不是自己仍在运行的开发服务器。演示可以换端口：

```sh
cd cloudflare
npm run demo -- --port 8790
```

随后打开 `http://127.0.0.1:8790`。不要为腾出端口盲目结束不认识的进程。

## demo 与自己的实例有什么区别？

| 操作 | 使用的数据与配置 |
| --- | --- |
| `npm run demo` | 虚构报价、演示站点配置、独立的 demo D1 |
| `npm run dev` | 自己的普通本地实例，需要先初始化、迁移和导入 |
| `python3 -m collector.update` | 读取自己的来源和目标配置，执行真实采集与推送 |

先在 demo 确认界面，再按[实例配置](configuration.md)准备自己的来源。
`--dry-run` 仍会访问原店，只跳过同步、AI 和推送；它不是离线测试模式。

## 实例初始化提示已经存在数据

初始化有意拒绝覆盖 `seeds.json` 或 `snapshot.json`。已有实例应继续使用原数据，
或通过 `BIJIA_DATA_DIR` 指定一个新的空目录。不要为重新初始化直接删除审核映射、历史库或检查点。

来源示例默认全部停用。请替换成自己的原店信息并显式启用。
初始化只导入一次来源清单；之后修改 `.local/sources.json` 不会自动修改已建立的实例，
需要在实例的 `seeds.json` 中管理来源。

## 采集成功，但没有可比价报价

分别检查以下环节，不要把“店铺能读取”等同于“商品已审核且有货”：

1. 来源是否启用，是否有当前适配器可读取的商品。
2. 商品是否完成首次详情分类，映射是否对应当前规格。
3. 价格是否有效，库存是否明确有货，是否超过报价有效期。
4. 标题关键规格是否变化，商品或店铺是否被暂停、排除。
5. 是否完成全部推送批次；`--dry-run` 不会更新线上。

`--no-ai` 不会批准新商品。已完成首次分类的店铺，新出现商品目前也不会自动加入原有分类计划。
采购前仍应在原店核对条款，后续价格更新不代表重新审核了全部商品说明。

## 推送返回 401 或 409

- **401**：检查目标实例和采集令牌是否匹配。采集令牌与后台密码分开使用；不要把值贴进 Issue。
- **409**：查看具体冲突，通常需要核对后台排除或审核映射与本地状态。
  不要跳过指纹检查或反复强推旧包。同步、重新审核或重新导出前，先保存当前任务与数据；
  修改后的导出包不能冒充原包继续旧计划。

普通网络中断可以用相同目标与参数执行 `--resume`，已接收的批次会保留。

## 价格更新是否需要重新部署网站？

不需要。采集完成后推送数据即可；代码、域名或构建时站点配置变化才需要重新构建部署。
采集成功、推送完成和页面缓存刷新是不同阶段。保留真实观察时间，不要通过改时间让旧报价重新有效。
