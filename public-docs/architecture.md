# Architecture

```text
Your allowlisted storefronts
  -> local Python adapters: shelves and original details
  -> first classification and source verification
  -> instance snapshot + history + resumable export
  -> authenticated, versioned batch transfer
  -> Cloudflare Worker validates and writes D1
  -> public queries / SSR / React frontend / caches
```

The Worker never needs to visit stores to publish local observations. Updating
prices writes data; it does not deploy site code. Source adapters and review
logic run locally or on the operator's own macOS/Linux machine.

## Boundaries

- `collector/`: Python standard-library collection, review and orchestration.
- `config/catalog.json`: starter specification definitions, without shop mappings.
- `config/site.json`: public defaults; `.local/site.json` overrides one installation.
- `.local/data/`: default private instance data directory. `seeds.json` contains
  the instance's shop configuration, specification snapshot, mappings and exclusions;
  `snapshot.json` contains actual collected observations. These formats are retained
  for compatibility. Their contents do not enter the public repository.
- `cloudflare/src/`: routes, services, imports, SQL repositories and SSR.
- `cloudflare/web/`: React frontend; `public/` is generated by Vite.
- `cloudflare/shared/`: eligibility rules, public types and transfer formats.
- `cloudflare/migrations/`: ordered, immutable D1 migrations.

The starter catalog is copied into a new instance at initialization. Afterwards,
the instance's catalog in `seeds.json` is authoritative for that collector. Changes
to the public starter catalog do not silently overwrite reviewed instance data.
Local configuration owns source URLs and specifications; authenticated backend
pause/exclusion state is synchronized before normal updates. Existing conflict
and fingerprint checks remain in force.

## Build-time site settings

`prepare-instance.mjs` merges public site defaults with the optional private
override and emits `cloudflare/.local/site.json`. Both the Worker and React import
that same public object. Only known public fields are included; never place secrets
in site configuration. Changing it requires rebuilding both sides with the npm
scripts. Direct Vite/Wrangler commands skip parts of this preparation.

## Scheduling

The initial release runs collection manually. The update command has a process
lock and durable checkpoints; batch transfers have hashes, server receipts and
retry support. An external scheduler can invoke the same command on one host,
but no cron, launchd, cloud trigger or live-collection workflow is installed.
Multiple writers sharing one instance are not supported; multi-node leases and
task distribution are future work.
